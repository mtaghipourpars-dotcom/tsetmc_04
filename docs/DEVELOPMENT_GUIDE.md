# راهنمای توسعه

ساختار: skills/ مشخصات قابلیت‌ها؛ docs/ معماری و حاکمیت؛ src/ کد اجرایی در فاز پیاده‌سازی؛ tests/ آزمون‌ها.

1. پیش از افزودن قابلیت، Skill مرتبط را پیدا یا ایجاد کنید.
2. ورودی، خروجی و وضعیت‌های خطا را تعریف کنید.
3. data lineage و data_class را حفظ کنید.
4. تست پذیرش را همراه تغییر اضافه کنید.
5. مجوز استفاده از وابستگی خارجی را بررسی کنید.
6. مستند وضعیت را به‌روز کنید؛ mock را LIVE معرفی نکنید.

کد باید قابل تست و بازتولید باشد؛ secret در repository قرار نگیرد؛ CI پیش از merge اجرا شود.
